# 翻訳繋ぎゲーム — 作業空間 要件定義（v1）

対象範囲は作業空間の1画面のみ。トップ、生徒の方へ、先生へ、フィードバックは今回作らない。

---

## 1. これは何か

生徒が英単語を1つ起点に、英和辞書と和英辞書を交互に引きながら、日本語と英語の語をつないだネットワーク（翻訳地図）を作っていく画面。紙とペンでやっていた活動の置き換え。

**このアプリが引き受けるのは、描画と記録とルールの保証だけ。辞書を引く行為は生徒の手元に残す。**

---

## 2. 作らないもの（仕様として明記）

以下は「未実装」ではなく「実装しない」。

- 訳語のサジェスト、オートコンプリート
- 辞書API、翻訳APIとの連携
- スペル修正、入力候補の提示
- 正解判定、点数

理由：辞書の項目を眺めて取捨選択する行為そのものが学習内容であるため。候補を提示した時点で誰の地図も同じ形に収束し、授業後半の比較が成立しなくなる。

---

## 3. データモデル

日本語ノードと英語ノードからなる**二部グラフ**。同じ言語同士は決して接続されない。

```
Node {
  id: string
  text: string          // 表示用の原文字列
  key: string           // 照合用。trim + 小文字化（英語のみ）
  lang: "ja" | "en"
  depth: number         // 起点語からのホップ数。起点は 0
  x, y: number
  pinned: boolean       // 手動で動かされたか
}

Edge {
  id: string
  from: nodeId          // 常に ja と en の組
  to: nodeId
}

Session {
  v: 1                  // データ形式のバージョン
  id: string            // 地図ID。リンクが指すもの
  seed: nodeId
  nodes: Node[]
  edges: Edge[]
  createdAt: string
  updatedAt: string
}
```

`depth` は「起点からの最短ホップ数」。再接続で経路が増えた場合は最小値を採る。

---

## 4. 守るべき不変条件

UIの制約として構造的に保証する。注意書きで守らせない。

1. **エッジは異言語間にのみ張れる。** 同言語のペアは生成不能であること。
2. **同じ語は1ノードしか存在しない。** `key` が一致する語が既にあれば新規作成せず、既存ノードへエッジを追加する。
3. **入力言語は自動で決まる。** 選択中ノードが英語なら入力は日本語、日本語なら英語。生徒に言語を選ばせない。
4. 自己ループと重複エッジは作れない。

---

## 5. 操作フロー

### 5.1 起点を置く

空の状態で英単語を1つ入力。これが depth 0 のノードになり、キャンバス中央に置かれる。

- 空状態のメッセージ：「英単語をひとつ置くところから始まります」＋入力欄
- 起点は英語固定（授業の運用に合わせる）

### 5.2 語を足す

1. キャンバス上のノードをクリックして選択する
2. 画面下部の入力バーが、選択語と次に入れるべき言語を表示する
   - 例：「引き分け を和英辞書で引く」／チップに「次は英語」
3. 生徒が手元の辞書を引き、拾った語を入力して「置く」
4. 複数語をまとめて入れられる（カンマまたは改行区切り）

### 5.3 既出語の扱い

入力された語が既に地図にある場合、新しいノードは作らない。

- 「`思う` はすでに地図にあります。線をつなぎますか」と確認
- 承認したら既存ノードへエッジを追加し、そのノードを一瞬強調表示する

この瞬間がこの活動の山場なので、演出をつける価値がある。ネットワークが閉じる体験。

---

## 6. レイアウト

**力学配置（force-directed）をそのまま使わないこと。** ノード追加のたびに全体が動くと、生徒が自分で作った空間の記憶を失う。

- 放射状配置。`depth` が半径を決める
- 角度は親ノードの方向を継承しつつ、兄弟間で分散させる
- **既存ノードは固定。** 新規ノードだけがアニメーションで着地する
- ドラッグで手動移動でき、動かしたノードは `pinned: true` になり以後自動配置の対象外
- ノード数が増えたらキャンバスをズーム／パンできる

---

## 7. ビジュアル方針

原則：**入力は素朴に、出力は美しく。** 装飾の予算は地図の描画に集中させる。

- **言語は書体で区別する。** 日本語は明朝系、英語は等幅系。色に頼らない
- **深さは濃度と字の大きさで表す。** 起点が最も濃く大きい。遠いほど淡く小さい。これにより「地図の先端がどんな語か」が一目でわかる（授業での比較観点そのもの）
- 線は極細のヘアライン。ノード同士の関係が主役で、線は背景
- 色数は最小限に保つ。強調（選択中、既出語の再接続）にのみ使う
- 背景は落ち着いたトーン。ライト／ダーク両対応

## 8. 画面構成

```
┌────────────────────────────────────────┐
│ draw     語数 9   深さ 2   先端 5       │  ヘッダー
├────────────────────────────────────────┤
│                                        │
│              （翻訳地図）               │  キャンバス
│                                        │
├────────────────────────────────────────┤
│ [次は英語] 引き分け を和英辞書で引く [置く]│  入力バー
└────────────────────────────────────────┘
```

**ヘッダーの指標**は授業の比較観点に直結させる。

- 語数：地図がどれだけ広がったか
- 深さ：起点から何回翻訳を往復したか
- 先端：これ以上たどっていない語の数

**選択状態**では、選択中ノードとそこから伸びる枝を強調し、それ以外を沈める。

---

## 9. 保存・再開・共有

地図に固有IDを振り、保存領域に置く。リンクは常にその最新の状態を指す。アカウントとログインは作らない。

### 9.1 リンクの3つの形

**起点語リンク**（先生が配る用）

```
.../workspace#w=draw
```

読めて、短く、口頭でも伝えられる。開くと `draw` が中央に置かれた状態で新しい地図が始まる。起点語は英語固定なのでパラメータは1つで済む。

**編集リンク**（本人が続きを作る用）

```
.../workspace#m=<地図ID>&k=<編集キー>
```

地図を最初に作ったときに発行され、そのブラウザに保存される。以後この地図の編集はこのリンクからのみ行える。

**閲覧リンク**（人に見せる用）

```
.../workspace#m=<地図ID>
```

編集キーを含まない。開くと地図は見えるが語を足せない。**先生や他の生徒に渡すのはこちら。**

### 9.2 保存の振る舞い

- 語を追加・移動するたびに保存する。ただし書き込みは束ねる（連続操作は1回にまとめ、1〜2秒待ってから送る）
- 保存中・保存済みの状態を画面に小さく表示する
- 保存に失敗しても操作は止めない。ローカルにも常に控えを持ち、復帰したときに送り直す
- 同じ地図を2箇所で同時に編集した場合は後の書き込みが勝つ。競合の解決はしない（1人1地図の運用を前提とする）

### 9.3 公開範囲の明示

保存された地図は、このアプリを使う人が閲覧できる領域に置かれる。**その旨を保存時に画面上で伝える。** 個人が特定できる情報は地図に含めない設計とし、氏名の入力欄も設けない。誰の地図かは、リンクを提出する側で管理する。

### 9.4 書き出し

リンクが生き物である以上、凍結した記録も必要になる。

- **JSON**：`Session` をそのまま出力する。後の比較機能・クラス集計はこのJSONを入力とするので、形式は今の時点で確定させておく
- **PNG**：印刷して並べられるよう、地図を画像で出力できる

### 9.5 授業での回収

提出用の仕組みは作らない。実施後アンケート（Google Forms）に閲覧リンクを貼る欄を1つ足せば足りる。

提出後も本人は編集を続けられる点に注意する。授業時間内の到達点を評価したい場合は、リンクではなくPNGかJSONを提出させる。

---

## 10. エラーと空の状態

- 空のまま「置く」→ 入力欄の下に「語を入力してください」
- 起点を置く前のキャンバス → 「英単語をひとつ置くところから始まります」
- 同じ語を同じ親に2回入れた → 「その線はもうあります」

エラーは何が起きたかと次の一手だけを言う。謝らない。

---

## 11. 動作環境

- PCブラウザを主対象。タブレット（横向き）でも操作できること
- スマートフォンは対象外でよい

## 12. 受け入れ条件

- [ ] 起点語を置いてから、10語以上のネットワークを一度も言語を選ばずに作れる
- [ ] 同言語同士をつなぐ操作が、UI上どうやっても実行できない
- [ ] 既出語を入力すると新規ノードが作られず、既存ノードに線が引かれる
- [ ] ノードを追加しても、既に置かれたノードの位置が動かない
- [ ] 訳語の候補がどこにも表示されない
- [ ] リロード後も作業内容が残っている
- [ ] `#w=draw` 形式のリンクを開くと、その語が起点として置かれた状態で始まる
- [ ] 編集リンクを別のブラウザで開くと、最新の状態が再現され、続きから語を足せる
- [ ] 閲覧リンクでは地図が見えるが、語を足す操作ができない
- [ ] 語を足した後で閲覧リンクを開き直すと、その変更が反映されている
- [ ] 手で動かしたノードの位置は再現され、動かしていないノードは自動配置される
- [ ] 保存された地図が他の人から見えることが、画面上でわかる
- [ ] 保存に失敗しても操作が止まらず、復帰後に反映される
- [ ] JSONとPNGで書き出せる

## 14. 将来の移行に備えて

このアプリは最終的にClaude Designの枠組みを離れ、独立したウェブアプリになる。そのための条件を今の実装に課す。**この3点以外は将来に備えない。**

### 14.1 保存の出入口を一箇所に閉じる

読み込み・保存・ID発行だけを担う薄い層を作り、画面とグラフのロジックはそこ以外の保存機能に触れない。移行時はこの層だけを差し替える。

```
loadMap(id) -> Session
saveMap(session) -> void
createMap(seed) -> { id, editKey }
```

### 14.2 グラフの処理を独立させる

以下は保存方法にも画面にも依存しない純粋な処理として書く。移行時に一行も変えずに移る部分であり、この活動の中身そのものでもある。

- 語の正規化と名寄せ（`key` の生成）
- 不変条件の判定（異言語間か、既出か、重複エッジか）
- 深さの計算（起点からの最短ホップ数）
- 放射状レイアウトの座標計算

### 14.3 データ形式にバージョンを持たせる

`Session` に `v: 1` を持たせる。形式を変えるときに、古い地図を読めるようにするため。

### 14.4 積み上げないもの

**編集キーの仕組みは間に合わせである。** 本物のバックエンドに移れば権限は仕組みとして持てるため、この方式は捨てることになる。ここに機能を追加していかない。
